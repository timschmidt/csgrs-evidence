# Complete-work cost protocol

The production baseline is clean82f31d335545510a5e5934e49e64540dda825295. Seven
candidate binaries from the previous sealed increment were copied only after
matching every recorded candidate source hash against that clean revision and
checking each executable's SHA-256 and byte count against committed evidence.
No frozen runner is executed or changed. New baseline invocations regenerate all
328 old archive records. Candidate programs preserve the same complete recipes,
assertions, materialization, validation and replay. The previously strengthened
polynomial_branches derivative success is now the same contract on both sides.

Thirty-eight preserved workflows run in three alternating baseline/candidate
process pairs pinned to CPU10. First-fresh-input and repeated-fresh-input phases
stay separate: these are complete newly constructed inputs, not repeated calls
on one prepared object. Source, compiler, features, dependency locks, iterations,
raw phase rows, allocator calls/requested bytes, process CPU and peak RSS are
retained. No separate build or test runs alongside measurement. Caches/warmth are not claimed
identical beyond the declared process and input protocol. Requested Rust bytes
are traffic, not live heap, and omit foreign allocator internals.

The eight new surface-differential workflows (seven shared tests plus the
native-NURBS supplement) have no successful production
baseline. Keep three absolute process samples and their exact completion/assertion
contract; an older Unsupported result is not a faster successful normal query.
Prototype timings and timeouts remain diagnostics, separate from matched costs.
Native and WASM size/hash records are separate from correctness and artifact
identity. The full earlier unfavorable observations remain open regardless of
this finite sample; the 10% review marker is not a statistical significance test.

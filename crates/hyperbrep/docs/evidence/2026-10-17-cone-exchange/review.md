## Native mathematical obligations

For generator `P+t*D` and unit axis a through C, set `c=D.dot(a)`,
`r=D-c*a`, `q=(P-C)-((P-C).dot(a))*a`. After proving c and r nonzero,
`t0=-q.dot(r)/r.dot(r)` is a candidate axis intersection. The additional exact
proof `q+t0*r=0` is necessary; merely projecting the lines would admit skew
generators. The apex is `A=P+t0*D`.

For a candidate point W, set `h=(W-A).dot(a)` and
`w=(W-A)-h*a`. Membership in the double cone requires
`c*c*w.dot(w)=h*h*r.dot(r)`. A nonzero h then selects the sign of `t-t0`
as `sign(h)*sign(c)`. The apex cannot select a branch. These are exact
equalities and inequalities, never tolerance tests.

Write `n=norm(D)`, `rho=norm(r)`, `alpha=atan(rho/abs(c))`, and let b be +1
for increasing generator parameters or -1 for decreasing parameters. The
native frame is `X=b*r/rho`, `Z=sign(b*c)*a`, `Y=Z.cross(X)`. Its chart is
`u_native=sign(b*c)*u_source`, `v_native=b*n*(t-t0)`. The determinant sign is
`sign(c)` on either branch. The public chart retains the recognized source,
branch, native surface and affine map. Mapping coordinates alone does not
prove selected-domain membership; native evaluation rejects negative slant V,
and face publication still requires whole-image and topology validation.

The independent test oracle rotates `P+t*D` by Rodrigues' formula, then
compares points and both transformed first partials. It checks the orientation
with the cross product of source partials. This avoids treating two wrappers
around the same recognition formula as an independent oracle. Rational frames,
both axis directions, three signed generator speeds, symbolic translations,
negative source parameters, the height-7 nonterminating apex, and exact near
misses are included. Further budgets, supplied-pcurve and whole-workflow
acceptance remain to be implemented and executed.

No production cone STEP support, cost improvement, complete work package or
release readiness is admitted at this checkpoint.

The first three native groups pass on the first implementation. They are
focused geometry evidence only. I/O boundary construction also needs a
canonical point inverse: it must prove selected-branch membership, preserve
slant distance, and use the existing native section and atan2 authorities.
The added query returns one longitude in `[0,tau)` and rejects apex ambiguity;
face assembly remains responsible for periodic lifts and whole-edge proofs.

## Export and import prototypes

Writer v1 emits nine complete states, but selects the nonterminating apex
of the height-7 cone too early. The retained anchor diagnostic shows finite
points and axis anchors at both cap heights. Rational conversion alone checks
number size, not decimal representability. Writer v2 checks decimal encoding
before selecting the anchor; all ten original states then export. The separate
OCCT 7.9.3.1 reader accepts every output as a valid single solid and agrees with
independently integrated volume/area at relative tolerance 1e-12. This is only
floating-point interoperability evidence. Native exact round trips remain open.

The STEP [surface-of-revolution definition](https://www.steptools.com/stds/smrl/data/resource_docs/geometric_and_topological_representation/sys/4_schema.htm#surface_of_revolution)
specifies rotation around AXIS1_PLACEMENT, source-context angular units for U,
and the referenced generator's parameter for V. The implementation derives its
native chart through ConicalRevolution; the I/O layer applies declared units
and retains a native-to-source map per face. Distinct branches share a source
entity ID but have distinct native cache keys. A vertex-only branch prepass
avoids recursion through supplied pcurves. Entity visits are charged normally;
only actual loop assembly charges edge-use cardinality.

Importer v1 recognizes both manual LINE frusta but their native solid build
fails with DegenerateShellVolume. The direct native `closed_cones` regression
reproduces this failure without STEP. The owner is HyperBRep's cone shell
certificate (P17–P20, P26, P35, P39): its whole-frustum branch additionally
requires four side faces and five U grid values, excluding one periodic side
face despite its validated full-circle edges and exact rectangular coverage.
Extend that declared representation domain by relying on the already-required
exact tau span, nonoverlapping complete grid coverage, whole-edge images,
oriented closed topology and cap grouping. Keep perturbed and repeated angular
coverage as independent rejection controls, and prove volume/area, near-boundary
classification, cold replay and further native Booleans for the original
5-to-2 height-6 case. This is a capability extension, not permission to skip
any geometric, topology or certainty obligation.

## Native continuation and explicit capability migration

The single-periodic-side acceptance retains the original 5-to-2 height-6
frustum, full-circle cap edges, reversed spatial curves and independently
shifted U charts. It proves exact volume/area and 1/10^12 classifications,
replays the native archive, and feeds ordinary Boolean operations. Missing or
repeated angular coverage remains rejected by the existing whole-image proof.
The early test named a nonexistent error variant and then expected the wrong
existing rejection category; both compiler/assertion failures remain retained.
The corrected test asserts the actual `EdgeUseSupportMismatch`, without changing
its hostile geometry or relaxing validation.

After exchange, the original band and lower remainder failed reunion with
`UnsupportedSolidShell`. Their native JSON inputs are retained both in evidence
and as deterministic regression fixtures. One chart used [-pi/2,0], the other
[3pi/2,2pi]. These are distinct parameter lifts of the same required angular
sector. HyperBRep now reduces only rectangle coverage evidence when the combined
raw span exceeds tau; original faces and pcurves are unchanged. Each rectangle
must have positive width at most tau. Canonical seam splitting produces at most
two rectangles, preserves multiplicity and V bounds, and leaves the existing
exact cell-overlap/completeness tests authoritative. No multi-turn rectangle is
collapsed. Unit tests include million-turn lifts, duplicate copies and 1/10^12
gaps. Both original reunion orders now pass independent measures, point
classification, cold replay and further native composition.

The original seam, coplanar and sector cone export fixtures initially failed
because their `unwrap_err` assertions received successful exact artifacts. The
full failed output is retained. Their modeled inputs remain unchanged; acceptance
now requires export graph/formula checks, exact reimport measures and topology,
and cold native replay. The previous irrational torus-band encoding control
still fails explicitly. Independent B-spline revolution, invalid/skew/off-carrier
geometry, malformed supplied-pcurve, duplicate seam, small-budget and irrational
split-vertex controls remain. This is a declared capability migration, not a
performance-only change.

for the nonterminating apex; two independent manual LINE inputs; axis/generator
reversals, signed/shifted parameters and independent units; supplied LINE pcurves

branches of the same source entity and that mutating a cloned report cannot alter
the cached map. Successful proofs are immutable and import-local; resource limits
remain cardinality and instrumented-solver limits, not total-work/heap/cancellation
certificates. Three closed-cone groups and two periodic-rectangle groups cover

The public example emits ten complete cone artifacts and asserts native measures,

`StepFile::syntax().entity` API. No production API was added for that mistake.
The new benchmark measures the complete exchange/continuation workflow, including
all assertions, materialization, provenance checks, cold replay and empty recovery.
It has no successful pre-extension baseline; only absolute cost is meaningful.

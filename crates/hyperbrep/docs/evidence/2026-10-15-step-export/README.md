# Exact native faceted STEP export — 2026-10-15

Partial WP14a implementation on baseline `25a48c202`; all 28 plan gates remain
open. This increment exports explicit native planar straight-edged solid
selections in exact decimal form, with shared native vertex identity, every
body/hole/edge use and source mappings. Cavity shells, curved carriers,
unmaterialized points and nonrepresentable numbers return typed errors.
See the [normative mapping](../../../../hyperbrep-io/docs/STEP_MAPPING.md).

The writer uses boundary-derived plane charts and implicit straight polygon
edges. It preserves selected geometry and oriented topology; original pcurves,
parameter domains, history and unrelated document records require native
persistence. `NonRational` reports the absence of a retained rational view, not
a theorem about irrationality. Byte/entity/segment and numeric encoder bounds
do not bound all scalar arithmetic, heap use or elapsed time.

## Validation and limits

- `commands.json` and logs: **359** combined native results (317 existing
  all-feature HyperBRep; 42 IO = one unit test, 38 integration tests, three
  doctests); all 42 IO results also pass in release. The new unit test checks
  600 signed/reduced finite decimal cases plus explicit spellings and prime
  denominator rejections. Strict IO all-target/all-feature Clippy, warning-denied
  rustdoc, workspace formatting and whitespace checks pass.
- Native integration cases inspect emitted coordinate values, normal direction,
  edge endpoint IDs and segment provenance directly against source geometry,
  separately from importer replay. They cover rational edge splits, shear,
  reflection, coordinates beyond `2^53`, a `1e-12` gap, repeated body occurrences,
  holes, oblique planes, units, encoded text and inclusive/retryable limits.
- `wasm-runtime.json`: five executed Wasmtime 38.0.0 groups, zero host imports,
  with reflected holes, repeated occurrences, exact volumes, source counts,
  Unicode, deterministic output, nonterminating/curved/limit rejections and
  independent string ownership. This is not production ABI qualification.
- `exports/` contains seven original native constructor/edit/transform recipes
  generated by the public example. `occt-read.json` records OCCT 7.9.3.1 reading
  every file, valid topology, expected unique counts and expected volumes. Inputs
  include a collinear split vertex, hole, reflection, concavity, two bodies and
  inch conversion. OCCT is an optional floating-point interoperability oracle,
  not an exactness proof or full EXPRESS/AP conformance validator.
- `controls/` preserves six deliberate fault patches and runtime-failing logs:
  silence a nonterminating decimal, drop a hole/body, reverse face sense, corrupt
  a source segment and ignore total output bytes. Source is restored in `finally`
  and hashed. The receipt verifier also rejects missing/duplicated/changed rows.

No new fuzz/ASan/lexicase campaign, full workspace/pre-push run, general STEP
interoperability corpus, global runtime bound or work-package completion is
claimed. The earlier archive-admission timing gate remains open. Native exact
models are the authority; external reader success cannot authorize rounding.

## Costs and reproducibility

`export-costs.json` reports six absolute allocation-instrumented cases over three
CPU-0 processes. `import-costs.json` reports seven unchanged importer cases over
three alternating baseline/candidate pairs. Complete text, receipts, fingerprints
and importer allocation counts are preserved. Timing uses total elapsed time
divided by iterations, not truncated printed per-iteration values. See
[PERFORMANCE.md](../../../../hyperbrep-io/PERFORMANCE.md) for scope and costs.
No equivalent previous export exists and no export speedup is claimed.

The baseline importer binary was frozen before release rebuilding and matches
the SHA-256 in the [preceding evidence](../2026-10-15-step-faceted/faceted-executable.json).
`executables.json` records both rebuilt binaries. `measure.c` from that evidence
collects child `wait4` RSS, avoiding inherited Python-launcher peak measurements.
The six core source trees and production dependency versions/sources/checksums
remain unchanged; only the IO lock entry gains the already-locked `num` dependency.

From the repository root, with the environment recorded in `environment.json`:

```sh
python3 crates/hyperbrep/docs/evidence/2026-10-15-step-export/controls.py
python3 crates/hyperbrep/docs/evidence/2026-10-15-step-export/qualify.py
python3 crates/hyperbrep/docs/evidence/2026-10-15-step-export/benchmark.py
python3 crates/hyperbrep/docs/evidence/2026-10-15-step-export/collect.py
python3 crates/hyperbrep/docs/evidence/2026-10-15-step-export/verify.py
```

The qualification script installs the recorded WASM probe into `/tmp`, not the
production workspace. Optional oracle wheels are acquired by the adjacent
[`fetch_oracles.py`](../2026-10-15-step-faceted/fetch_oracles.py), with pinned
versions/hashes in that evidence. Benchmark reproduction needs a baseline
`faceted` executable built at `25a48c202`, copied to
`/tmp/hyperbrep-import-before-export` before building this increment; the script
checks its recorded digest. Native Cargo invocations are offline and locked.
`verify.py` checks source/artifact hashes, command exits, runtime/oracle results,
fault controls, benchmark receipts/costs and open ledger gates without rebuilding.

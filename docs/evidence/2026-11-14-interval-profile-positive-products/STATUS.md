# Positive transmission interval-chain experiment

Disposition: rejected. No production code or public API from this experiment is
retained. Phase8 and the complete fifteen-phase goal remain open.

The clean targets are CSGRS 9ee4375ed568e434bc81838199fd9fda765bead4 and Interface
b4a15bd0c281cb63ecc3c1d3d451144041c85f91. The main 41 staged extraction paths and
Interface's eight edits were excluded from isolated worktrees. BASELINE.json
records their exact states; none is reset or accepted by this experiment.

This differs from the earlier rejected constructor-only experiments. The new
hypothesis combined unsigned-radius ingress with a retained nonempty positive
rational interval proof, a four-factor product and a positive quotient. Interface
kept nominal values, units, public ExactInterval layout/getters/Debug, physical
fact errors and configuration identity. Lower products precede upper products;
nominal division precedes lower/upper division. The new temporary proof carrier
has no unchecked constructor or serialized flags. General RationalInterval empty
and signed operations are unchanged. Hyperreal source and compiler flags were
not modified. ADMISSION.md states the pre-edit contract.

The missing owner API failed to compile on the target before production edits.
The final candidate passes eleven owner test reports in three harnesses: three
unsigned-radius cases, five positive-chain cases and three existing rational
cases. These include 625 independent integer-corner transmission chains, an
independent GMP large-rational oracle, generated output consumed again,
zero/one-factor identities, empty/nonpositive/reversed rejection, the retained
original empty domain and fresh-process original/new dispatch equality for
small/large cold/warm chains. The prior unsigned-radius tests are reused without
weakening assertions. This is a finite corpus, not a universal implementation
proof or a completed interface migration.

Seven full native profile/identity transcripts match baseline, including six
successes and the expected invalid profile. All seven raw warmed allocation,
deallocation, reallocation, allocated-byte, peak and signed-live rows match.
WASM reproduces every corresponding native transcript, rejects invalid output
indices/case and makes zero host calls. Native/WASM matching is a consumer
boundary check, not an independent full-profile mathematical oracle.

GNU size's combined text/read-only-data column grows 586417 to 587241 (+824);
its other columns and the complete file sizes are retained in the build records.
BSS falls and its aggregate dec total falls by eight bytes, but that is not an
executable-file or code-size improvement. No gate is waived using that aggregate.
Build durations, Wasmtime fuel and concurrent validation are not wall-time
performance comparisons. No owner/downstream timing campaign, full-profile
both-policy dispatch comparison, full schedule/browser suite, monomorphized
function attribution or full pre-push matrix was run after the size rejection.

Strict owner all-feature/all-target Clippy initially rejected the new consuming
`div` name as confusable with the standard trait. The prototype uses `quotient`
instead, and its test records the original nonpositive comparison before an
assertion. Strict Clippy and the eleven focused reports then pass. The final
native and WASM executables are byte-identical to their initial candidate
counterparts: correcting the lint did not remove the size failures.

The copied old harness locks initially needed refresh for the current local
package graph. Both were resolved offline before any candidate build and then
held fixed with --locked. The old locks, new metadata and stderr are retained.
The first WASM replay invocation used system Python without Wasmtime; its import
failure is preserved. Replay uses the existing tool environment with Wasmtime
50.0.1. These are harness failures, not accepted geometry/profile results.

All candidate source, patches, input fixtures, initial failures and completed
consumer outputs remain in this record. The isolated source is restored to its
starting commits. Post-restoration owner checks and fresh native/WASM rebuilds
are recorded separately. No new source is integrated into either authoritative
repository. Further work needs a supported way to remove the demonstrated
consumer artifact growth; do not repeat this carrier/constructor design or
substitute an isolated arithmetic win for the complete profile contract.

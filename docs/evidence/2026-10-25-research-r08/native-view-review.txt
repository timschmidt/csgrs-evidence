R08 native closure continuation review (pending experiment)

CurveRegionBoundaryLoop2 already stores a connectivity policy and replay_connectivity observes it. Native Contour2 and CurveString2 have no field retaining that qualification; their checked constructors demand strict connection. Merely replacing a checked constructor with from_validated_closed_segments can therefore create a public native view whose subsequent closed-contour queries have no way to account for the original terminal-dependent closure. The temporary connection-prototype measures this path, including strict native classification and rebuilding a CurveRegion2 from the view, before any proposal is retained.

Separately, transform_affine_raw seeds line_image_region with certify even after an approximate operation. The temporary prototype only seeds that slot for a strict retained result. Native contour extraction must otherwise go through the existing policy-aware classification cache so a later strict request cannot use an approximate closure as certified. This precaution is part of the experiment, not a claim that all native views now retain their dependencies.

Candidate designs still to compare if the prototype loses qualification: carry a private connectivity/closure policy in native contour/string carriers and gate all consumers that depend on it; or use a scoped native modeling projection with explicit fidelity and provenance, keeping the authoritative region qualified. Preserve source endpoints and current exact native controls. Do not add unconditional approximation, promote a qualified contour silently, or label a sampled replacement lossless.
